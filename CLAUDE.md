## Hard rules
- **NEVER commit** `data/` (patient records), `config.json` (device key + data_key), `users.json` (PIN hashes), `hub.pfx`/`hub.cer`, `backup/`, `neosoft.json`, `neosoft-skema.txt` (.gitignore covers them — keep it that way).
- **NeoSoft DB is read-only.** SELECT only. Never write to the live NeoSoft database. Never put DB credentials in any committed file.
- **Restyle ≠ relogic.** When changing look/layout, keep every `id` and JS function intact. Engines read fields by id/label: `buildIntake()` (F1), `applyIntake()`, `applyHandoff()`, `buildHandoff()`, `reqStatus()`, `igaData()` (F2).
- Forms are **offline-first**: hub calls are optional and wrapped in try/catch; downloaded JSON files remain the backup in every path. Don't make the hub mandatory.
- No instruction text inside forms (moved to the Panduan). Patient-facing text in Form 1 stays.
- User-entered text renders blue (`--ink-fill:#1F4E9C`). Section codes D0–D8/K1 (`.sec .n`) are print-only since 2026-11-06 (hidden `@media screen`); on-screen copy refers to steps as "langkah N (rail label)" and never to D-codes. Vocabulary: IGA 0–4 is the grade ("Sedang (Moderate)"), program stages are "Tahap 1–4" (acne tags) / "Tahap A–C" (melasma) — never reuse a grade word as a stage tag. Dates shown to staff use `_tglID()` (id-ID short), not ISO. Button colour rule (2026-10-27): terracotta `--accent-act` = advance/commit inside the form (Lanjut, Serahkan, modal part nav, "Selesai — tutup & simpan", dialog OK); ink `--ink` = the irreversible publish only (`.nb-terbit` Terbitkan Handoff); everything else outlined. Modal footer has only "Cetak program ini" (outlined); closing is × or "Selesai". Touch targets ≥44 px (mode buttons, WAJIB chips (rendered as `<button class="it">`, OK chips disabled) and the "+N lagi" toggle, modal checklist rows, nav buttons, HUB chip, toolbar buttons, Rx "Pakai"/picker/tambah/hapus, ICD buttons and chip removers (`button.x[aria-label]`), `#hobar` action + override, allergy "Nihil", hand-over jump links, schedule cells, login dialog buttons — since 2026-11-06) and functional text ≥12 px; inputs use `<label class="lab" for>` (converted 2026-10-25, keep using labels for new fields); everything still unnamed gets a name at load from `initAriaNama()` (`span.lab` → id + `aria-labelledby`, `<label>` without `for` → `for`, table cells → "column — row", `.ln` → nearest `.q`, else `data-ph`/placeholder; also on `focusin` for added Rx rows), `.sec`/`.sec-label` carry `role=heading`, `.page` is `role=main`, IGA buttons sync `aria-pressed` (`_igaPressed`), every `.mdlg[role=dialog]` has `aria-labelledby`, and the HUB chip is a `<button>` in all 4 forms; rail buttons carry `aria-current="step"`. Contrast floor 4.5:1 for all text incl. placeholders (2026-10-25): placeholders use `--ink-muted`, secondary text `--ink-faint:#6F685B`, text on the dark toolbar/modal header `--ink-on-dark`, status green `--green-text`, white-on-terracotta buttons use `#B0603F`/`--accent-act`, never `#C97A5E`.

## Known gotchas (each bit us before)
- **Dual-role CSS classes** (incl. `.fin` = allergy-flag input, so never use it for a button — the modal finish button is `.pm-selesai`): `.sec`, `.row`, `.opt`, `.f`, `.ck` mean different things in main form vs. the Hair-Loss modal (`#ovl_hair`, imported markup). Any global style change must be checked for leakage into `#ovl_hair`.
- Phone (≤640 px) rules live in one `@media (max-width:640px)` block near `.tb-more`: toolbar and ctlbar wrap and go static, the acne 4-factor table stacks per row; plus small blocks next to their base rule: the D5 table sits in `.tblwrap` (scrolls sideways, min-width 600 on phones), the modal `.pmrail` is static on phones, and the login dialog's buttons stack at ≤480 (inside `_ldlgBuat`'s style string, all 4 forms). Shipping size is still the 1024 tablet; check both when touching chrome.
- Grid span classes differ per file (`.k4` exists in Form 2, not Form 1). Check definitions in the target file.
