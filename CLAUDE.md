# CLAUDE.md — ADC Hub / Skin Quality Program forms

Clinical forms + companion server for Aesthetic Derma Centre (Bandung) — Skin Quality
Program (Acne, Hiperpigmentasi/Melasma, Hair-Loss). Owner: Alex. UI language: Bahasa
Indonesia (all form/patient text). Code comments: Indonesian is fine.

## Layout & source of truth
- **Form sources live one level up** in `../` (the Marketing folder):
  `../ADC_Form1_Registrasi_Anamnesis_Pasien.html` (nurse+patient intake, new patients only),
  `../ADC_Form2_Asesmen_Umum_Dokter.html` (doctor assessment, contains program modals),
  `../ADC_Panduan_Pengisian_Form.html` (how-to guide — ALL instructional text lives here, not in forms).
- Also served by the hub (same copy rule): `../ADC_Form_Asesmen_Slimming_SpGK.html` (Sp.GK Slimming; has Muat Form 1 + hub) and `../ADC_SkinQualityProgram_Journey_Outcome_Tracker.html` (loads handoff by RM). Their hub/dialog code is a verbatim copy of Form 2's (`hubDefault…hubGetPasien`, `_dlgMuat`); change Form 2 first, then re-copy.
- `www/` holds **copies** served by the hub. Edit the `../` sources, then sync with
  `update-forms.bat` (or `push.bat`, which syncs + commits + pushes). Never edit `www/` directly.
- `server.js` — zero-dependency Node stdlib server (port 3777): serves `www/`, stores
  intake/handoff/consent per No. RM under `data/<RM>/`. Key in `config.json` (header `X-ADC-Key`). Optional `"webhook"` in `config.json` = Make.com URL, returned by `/api/ping` so every form pre-fills `cfg_webhook` (also remembered per device in `localStorage.adc_webhook`).
- **Compliance layer (2026-10-23, PMK 24/2022 / PP 28/2024 / KMK 1983 PKP 12 / UU PDP):** every `/api/*` except `ping` and `login` needs a user session (`X-ADC-Token`) on top of the device key. Users live in `users.json` (gitignored; scrypt PIN hash; roles admin/dokter/perawat/cs; first run prints a random admin PIN; manage with `tools/pengguna.js`). Rights table `HAK` in server.js (cs read-only, admin only for users/audit/late corrections). `data/_audit.log` = append-only JSONL (each line encrypted) of login/lihat/intake/handoff/consent/tolak/backup with user, rm, ip. Server stamps `_audit{oleh,nama,peran,waktu,ip}` into every stored doc. Intake re-save >2×24 h after the last `_audit.waktu` → 403 unless admin (archived copies keep both). `POST /api/ttd {id,pin,rm}` verifies a doctor's PIN (any logged-in session may ask) and returns an HMAC stamp stored as `penerbitan.ttd`; server sets `_audit.ttd_valid`. `POST /api/consent` stores `consent_<no>.json`; `/api/pasien/:rm` lists them. All `data/` files are AES-256-GCM envelopes keyed by `config.data_key` (auto-generated; legacy plaintext still readable; losing config.json = losing data). `backup_dir`/`backup_jam`/`backup_simpan` in config → mirror `data/` on start + periodically (`backup.bat` = manual). `hub.pfx` present (from `tools/buat-sertifikat.ps1`) → HTTPS. CORS header list must keep `X-ADC-Token`.
- Form side (shared block in all 4 forms, Form 2 is master): `hubTok/hubHdr/_hubCekSesi/_hubChipUser/hubMenu/hubLogin/hubTTD/_ldlg` — chip click = `hubMenu()` (login dialog with "Keluar" + link to `hubSetup`); `hubPost`/`hubGetPasien` retry after login on 401 `error:'login'`; chip class `warn` = hub up, not logged in. `issueHandoff` (F2 + Slimming) is split: TTD PIN dialog → `_issueLanjut(h[,a])`; cancelling records `ttd:null` ("sign-off tanpa verifikasi PIN"). In Form 2 the PIN is asked first when `d8_signoff` is ticked (`signoffTTD()` → `window._ttd`, status in `#d8_ttd`, `d8_tgl` prefilled); `buildHandoff` reads `window._ttd`, so Terbitkan only asks again when it is missing. `_ldlg` keeps one active dialog (`window._ldlgAkhir`): opening another closes the previous with `cb(null)`. Form 2 also has: ICD-10 picker (`ICD10` list, hidden `#d2_icd` JSON → `asesmen.icd`, carried at kontrol via `_bawaKontrol`), per-section `waktu_isian` (document-level input/change listener → handoff), consent generator (`bukaConsent/consentHTML`, `IC_RISIKO` risk library, `#d8_consent_no` → `penerbitan.consent_no`; sheet is printed and signed on paper, `d8_consent` stays a manual checkbox). Form 1: `p_nik` (16-digit, `cekNIK`) → `pasien.nik`; P6 has a hak/kewajiban box and 7 `label.ack` (3 new with `data-k=hak|umum|pdp`) → `persetujuan.butir/umum/data_pribadi/hak_kewajiban`. Consent/explanation texts are drafts for the PJ klinik to review (Panduan §9).
- `neosoft-explore.js` — read-only NeoSoft Cube DB schema explorer (needs `npm i mysql2`
  + local `neosoft.json`). Run on clinic PC only.
- Launch Claude Code from here with the parent added: `claude --add-dir ..`

## Hard rules
- **NEVER commit** `data/` (patient records), `config.json` (device key + data_key), `users.json` (PIN hashes), `hub.pfx`/`hub.cer`, `backup/`, `neosoft.json`, `neosoft-skema.txt` (.gitignore covers them — keep it that way).
- **NeoSoft DB is read-only.** SELECT only. Never write to the live NeoSoft database. Never put DB credentials in any committed file.
- **Restyle ≠ relogic.** When changing look/layout, keep every `id` and JS function intact. Engines read fields by id/label: `buildIntake()` (F1), `applyIntake()`, `applyHandoff()`, `buildHandoff()`, `reqStatus()`, `igaData()` (F2).
- Forms are **offline-first**: hub calls are optional and wrapped in try/catch; downloaded JSON files remain the backup in every path. Don't make the hub mandatory.
- No instruction text inside forms (moved to the Panduan). Patient-facing text in Form 1 stays.
- User-entered text renders blue (`--ink-fill:#1F4E9C`). Touch targets ≥44 px (mode buttons, WAJIB chips, modal checklist rows, nav buttons, HUB chip) and functional text ≥12 px; inputs use `<label class="lab" for>` (converted 2026-10-25, keep using labels for new fields); rail buttons carry `aria-current="step"`. Contrast floor 4.5:1 for all text incl. placeholders (2026-10-25): placeholders use `--ink-muted`, secondary text `--ink-faint:#6F685B`, text on the dark toolbar/modal header `--ink-on-dark`, status green `--green-text`, white-on-terracotta buttons use `#B0603F`/`--accent-act`, never `#C97A5E`.

## Data contracts (JSON)
- `ADC-INTAKE v1` (Form 1 → Form 2): `pasien{nama,rm,wa,tanggal,…}`, `kritis{alergi,…,flags}`, `penugasan{dokter,foto_baseline,foto_area}`, `pengukuran{bb,tb,imt}`, `persetujuan{…,tanda_tangan}`.
- Hub stores Slimming handoffs separately (`handoff_terakhir_slimming.json`, `handoffslim_<stamp>.json`; `/api/pasien/:rm` returns both); Form 2 refuses `sumber` ADC-SLIMMING-*. `pasien.hormonal`/`pasien.flags` ride in the handoff so the D7 drug gate sees pregnancy at kontrol visits. Acne modal Rx placeholders/cautions follow Dr. Oku's 4-factor note (Panduan §8). Program modals are 3-part wizards built at load by `initPmWizard()` (wraps existing nodes into `.pmpart[data-part=1..3]` by section letter A,B / C,D / E–G; `.pmrail` + `.pmnav`; `pmGo(p,n)`; print shows all parts). Markup and ids untouched, so readers are unaffected; hidden parts are still read. Acne B "Risiko bekas" = factor checkboxes (`.rbf`, labels unchanged) + radio `rb_level` suggested by `syncRisikoBekas()` (1 factor Sedang, ≥2 or Nodulokistik Tinggi; manual pick ≠ suggestion sets `_rbOverride`); `_progDetail` records checked radios as "<question>: <label>".
- `ADC-HANDOFF v1` (Form 2, every visit): `asesmen{dokter,diagnosis,pemeriksaan{…},resep[],…}`, `program_detail{acne|melasma|hair}`, `jadwal[]`, `riwayat[]` (cumulative — newest handoff carries the whole history), `kunjungan_ke`, `penerbitan{signoff_dokter,…}`.
- IGA (FDA 0–4) entered once in Form 2 D1 via buttons (hidden inputs `ac_iga`/`me_iga`); modals show read-only mirrors. Success = IGA ≤1 AND drop ≥2 from baseline (`iga_baseline` anchored at visit 1, carried in handoff).

## Form 2 structure (current)
Steps (6, since 2026-10-24 layout pass): 0 Handoff & riwayat (D0 incl. patient identity) · 1 Pemeriksaan & diagnosis (D1 + IGA panel; K1 in kontrol mode) · 2 Program (D2, hidden & skipped in kontrol mode) · 3 Resep, ritme & rencana (D3, D4, D5) · 4 Sign-off dokter (D6, D7; ends with "Serahkan ke perawat") · 5 Penjadwalan & terbit (D4b, D8 = d8_by/d8_status, primary **Terbitkan Handoff** button in the stepnav). Toolbar = HUB chip, Muat Form 1, Muat Handoff, Cetak/Simpan PDF + "Lainnya" menu (`tbMenu()`: Terbitkan copy, Cetak semua program, Reset).
Hand-over: "Serahkan ke perawat" calls `serahkanKePerawat()` (review dialog `#sdlg` from `_serahData()`: unmet `reqStatus()` items as jump buttons, `_ttd` state, program/stage, Rx count, rhythm); `renderSerahRingkas()` paints the same into `#serah_ringkas` at the top of step 6 (on `goStep(5)`/`updateReq`) and prefills `d5_by`/`d8_by` from `_hubUser`. The schedule lock message links to `d5_iv` via `goTo`.
WAJIB strip (`#reqbar`, rendered by `updateReq()`) shows only unmet chips plus the count (at most 3 unmet visible, the rest behind "+N lagi"); `.it.ok` are hidden unless `.semua` (toggle `toggleReqSemua()`); the `.ctlbar` wraps instead of scrolling horizontally.
Kontrol mode = `body.mode-kontrol` (`.vis-awal` hidden, `.vis-kontrol` shown); issuing a handoff is blocked until the previous handoff is loaded (`hoBelumDimuat()`), unless `ho_absen` is checked (audit-flagged).

## Known gotchas (each bit us before)
- **Dual-role CSS classes**: `.sec`, `.row`, `.opt`, `.f`, `.ck` mean different things in main form vs. the Hair-Loss modal (`#ovl_hair`, imported markup). Any global style change must be checked for leakage into `#ovl_hair`.
- Phone (≤640 px) rules live in one `@media (max-width:640px)` block near `.tb-more`: toolbar and ctlbar wrap and go static, the acne 4-factor table stacks per row. Shipping size is still the 1024 tablet; check both when touching chrome.
- Grid span classes differ per file (`.k4` exists in Form 2, not Form 1). Check definitions in the target file.
- Avoid `border` shorthand with `var()` where tests run in jsdom — use longhands.
- **Dialogs**: every `.mdlg-bg` dialog (Muat, Rx picker, ICD-10, consent) opens via `dlgBuka(bg, tutup)` and closes via `dlgTutup(bg)` (shared block in all 4 forms): Escape, focus trap, one dialog at a time, focus restored. The login/TTD dialog (`_ldlg`) closes any active dialog except Muat (`#mdlg`), which must stay open for the 401 → login → retry flow. Close labels: pickers "Tutup", forms "Batal".
- Editing markup: delete exact element ranges (balanced-div scan), never broad regex — an earlier edit silently deleted the Acne program card.

## Testing
No browser in the sandbox; tests use jsdom (`npm i jsdom css-tree` in a temp dir). Standard checks after every change: CSS parse (skip `<style>` blocks containing `'+`), `node --check` on extracted scripts, duplicate-id scan, plus a functional run through the real click paths (save intake → load in F2 → IGA → issue handoff → reload as kontrol). For hub tests, start `node server.js` and run the test in the same shell session.

Automated end-to-end: `node e2e-test.js` (178 checks; runs on a temp copy of `server.js` + `www/` with its own `users.json` (PINs in `PIN`), `backup_dir`, jsdom auto-installed to temp, real `data/` untouched; `disk()` decrypts with the temp `config.json` data_key). Run `update-forms.bat` first so `www/` is current. Covers F1 → hub → F2 → handoff #1 → two chained kontrol handoffs, login/roles/audit/2×24 h correction/TTD (valid + forged)/consent/ICD/encryption/backup, login dialog from a form, hub auth/path guards, offline fallbacks. `terbit(x,{pin,batal})` drives the TTD dialog. Not covered: signature canvas, print/popup layout, HTTPS, real tablets.
Kontrol handoffs carry diagnosis/pemeriksaan (tipe kulit, Fitzpatrick)/resep/program tahap forward from the loaded handoff when empty today (`_bawaKontrol()`, listed in `asesmen.dibawa`); values entered today always win.

D1 data rules (2026-10-08/09): allergy is entered in Form 1 for new patients (Form 2 hides the editable box when an intake is loaded; shown in Ringkasan), but is editable in Form 2 when no intake is loaded (kontrol). `d2_derajat` is computed from IGA (`_derajatTeks()`), not typed; a Derajat chosen before any program (`d1_iga`) is applied only when a program STAGE is picked (or the program is in the handoff). `d2_hasil` = "Catatan klinis" (temuan + penunjang); `d1_umum` is a hidden legacy field.

Hub result is surfaced, never silent: Form 1 Save waits for the hub reply and alerts "✓ tersimpan di hub (RM)" / "✗ GAGAL" / "TIDAK tersambung"; Form 2 Terbitkan writes ✓/✗/HUB MATI into `d8_status` and alerts on failure when the hub is up. Keep it that way.
Step order in Form 2: D4b (nurse scheduling) lives in step 6 after the doctor's sign-off step, so the device changes hands once. D1 is findings (`d2_hasil`) → diagnosis → derajat. Print-only residue (`.sigs`, `.stamp`, `.foot`, `.disc`) is hidden with `@media screen` and still prints; kontrol rail shows step 3 dimmed "dilewati" instead of removing it; `k1_arah` reads "Acne turun 2 (−2)" / "tetap (IGA sama)". D7 has two gate checkboxes recorded in `penerbitan`: `consent_tindakan` (warned when any procedure is checked or `k1_tindakan` filled) and `skrining_obat` (row shown only when `_obatBerisiko()` matches `OBAT_RISIKO`; Terbitkan warns, and puts a PASIEN HAMIL/MENYUSUI line first when Form 1 says so). Pregnancy is also visible while prescribing: `renderHamil()` (called from `renderSkrining()`) shows `#hamil_box` (D0) and `#hamil_box_rx` (above the D3 mirror), `renderRxMirror()` marks risky rows `tr.rx-risk`, and the skrining label gets `.lbl-hamil`; `applyHandoff` calls `updateReq()` so kontrol visits show it immediately. Inside the program modals: `renderHamilModal(p)` (from `openProg`, `renderRxMirror`, `closeRxPick`) inserts a `.rxhamil` band before every `.rx-table`/`#hr_rxTable` and marks rows `tr.rx-risk` via `_markRxRow` (also on `input`, capture phase); `openProg` adds a `.ctx-hamil` chip to the context strip. These record that the clinic's own consent/screening happened — the wording is not legal consent text. Form 1 staff panel: `p_foto_izin` (verbal photo consent) must precede `p_foto_ok`.
